## 新增案例

1. 先按软件、报错原文和现象检索已有案例，避免重复。
2. 复制模板到对应分类目录，文件名使用小写英文和连字符。
3. 分配唯一 ID：建议 `KB-TS-COMSOL-0001` 或 `KB-TS-ANSYS-0001`，先检查编号未被使用。
4. `domain` 为 `simulation`，`document_type` 为 `case`，保留 `troubleshooting` 标签并补充问题关键词；记录准确的软件和模块版本。
5. 登记来源与自有复现证据，填写适用条件、排查过程、无效尝试、设置变化和验证结果。未解决案例仍为 `draft`。
6. 在软件索引中增加链接和状态；审核沿用 [协作规范](../../CONTRIBUTING.md)。

## 在 VS Code 项目中使用

按软件版本、物理场和问题现象选择案例，同时带上关联的材料、模型及验证文档；保留引用路径或附依赖清单。要求助手先比较本次任务与案例的适用条件，再提出修改建议。草稿仅作人工排查线索，不直接生成工程设置。

README、模板及待收集主题不进入正式 RAG 索引；正式案例按 [RAG 规范](../../shared/rag/README.md) 审核后入库。
